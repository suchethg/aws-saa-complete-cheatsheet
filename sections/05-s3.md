


# **S3 — Simple Storage Service**

Amazon S3 is an object storage service offering industry-leading scalability, data availability, security, and performance. S3 stores data as objects within buckets. S3 is a key topic on the SAA-C03 exam, covering storage classes, security mechanisms, replication, performance tuning, and object versioning.

---

## **S3 Storage Classes — Pick the Right One**

S3 provides specialized storage classes suited for various access patterns, latency requirements, and cost structures.

| Storage Class | Use Case | Min Duration | Min Object Size | Retrieval Time | Cost Pattern / Key Features |
| ----- | ----- | ----- | ----- | ----- | ----- |
| **S3 Standard** | Frequently accessed data, active data sets | None | None | Milliseconds | Highest storage cost; no retrieval fees. |
| **S3 Intelligent-Tiering** | Unknown, unpredictable, or changing access patterns | None | None (`< 128 KB` auto-kept in Frequent) | Milliseconds (Standard) | Small monthly monitoring fee per object; automatically moves objects between access tiers with zero operational overhead and no retrieval fees. |
| **S3 Standard-IA** | Infrequently accessed data requiring rapid (ms) access when requested | 30 days | 128 KB | Milliseconds | Lower storage cost than Standard; retrieval fee applies. **High throughput, low latency (same as S3 Standard).** |
| **S3 One Zone-IA** | Non-critical, recreatable, infrequently accessed data | 30 days | 128 KB | Milliseconds | 20% cheaper than Standard-IA; single-AZ storage (data lost if AZ is destroyed). |
| **S3 Glacier Instant Retrieval** | Long-term archives requiring immediate access (e.g., medical images, news assets) | 90 days | 128 KB | Milliseconds | Low-cost archive storage with millisecond retrieval performance. |
| **S3 Glacier Flexible Retrieval** | Archives where flexible retrieval speed is acceptable | 90 days | 40 KB | Expedited (1–5 min), Standard (3–5 hrs), Bulk (5–12 hrs) | Very low cost; retrieval fee depends on tier selected. |
| **S3 Glacier Deep Archive** | Long-term compliance, financial records, digital preservation (7–10 years) | 180 days | 40 KB | Standard (12 hrs), Bulk (48 hrs) | Lowest cost storage in AWS; longest retrieval times. |
| **S3 Express One Zone** | High-performance, latency-sensitive ML/AI or analytics workloads | None | None | Single-digit ms | Directory-bucket architecture; highest performance; single AZ. |

## **S3 Lifecycle Management Rules**

* **Transition Actions:** Defines when objects transition to another storage class (e.g., transition to `Standard-IA` after 30 days, `Glacier` after 90 days).
* **Expiration Actions:** Configures when objects expire and are automatically deleted (e.g., delete log files after 365 days).
* **Noncurrent Version Management:** Configures lifecycle rules specifically for older, noncurrent versions of objects when versioning is enabled.

## **S3 Security & Access Management**

S3 security evaluation follows a simple rule: **An explicit DENY always overrides any ALLOW.** Effective access is the logical intersection of all policies.

### **1. Access Control Mechanisms**

| Mechanism | Scope | Primary Use Case |
| ----- | ----- | ----- |
| **Bucket Policy** (Resource-Based) | Bucket + Objects | Grant cross-account access, enforce HTTPS (`aws:SecureTransport`), enforce encryption rules, configure public access. |
| **IAM Policy** (Identity-Based) | User, Role, Group | Control what an internal IAM principal can do across S3 buckets. |
| **S3 Block Public Access** | Account or Bucket | Account-wide or bucket-wide override that blocks public policies and ACLs. First line of defense against accidental public exposure. |
| **S3 Object Ownership** | Bucket | Disables ACLs entirely and ensures the bucket owner owns all objects uploaded to the bucket. |
| **VPC Gateway Endpoint Policy** | Endpoint | Restrict S3 bucket access originating strictly from inside a VPC. |

| ⚠️ EXAM TRAP: Enforcing HTTPS Traffic: To mandate SSL/TLS in transit, add a bucket policy with `"Effect": "Deny"` when `"aws:SecureTransport": "false"`. |
| :---- |

### **2. S3 Encryption Types**

| Encryption Type | Key Manager | Key Details & Exam Keywords |
| ----- | ----- | ----- |
| **SSE-S3** (AES-256) | S3 Managed Keys | **Default encryption** for all new objects since 2023. No extra charge or key management overhead. |
| **SSE-KMS** | AWS KMS | Provides CloudTrail audit logging for every decryption call. Supports customer-managed keys (CMKs) and key rotation. |
| **SSE-C** | Customer Managed | Customer provides their own encryption key in the HTTP header on every request. S3 executes encryption/decryption and discards the key. Must use HTTPS. |
| **Client-Side Encryption** | Customer (Local) | Data is encrypted by client applications before being transmitted across the network to AWS S3. |
| **DSSE-KMS** | AWS KMS | Dual-layer server-side encryption with KMS for defense-in-depth compliance requirements. |

---

### **3. Object Lock & Compliance (WORM)**

* **WORM Model:** Write Once, Read Many. Prevents objects from being deleted or overwritten for a fixed retention period.
* **Compliance Mode:** Retention period **cannot** be bypassed by any user, including the AWS account root user.
* **Governance Mode:** Specific users with special IAM permissions (`s3:BypassGovernanceRetention`) can alter retention settings or delete the object.
* **Legal Hold:** Places an indefinite hold on an object until explicitly removed. Independent of retention periods.

## **S3 Versioning & Replication**

### **Versioning Mechanics**
* **MFA Delete:** Requires an MFA token to permanently delete an object version or suspend bucket versioning. Must be enabled via AWS CLI using the root account.
* **Delete Markers:** Deleting an object in a versioned bucket creates a 0-byte **Delete Marker**. The object appears deleted, but previous versions remain intact and recoverable. Deleting the Delete Marker restores the object.

### **Replication Features**

| Feature | Cross-Region Replication (CRR) | Same-Region Replication (SRR) |
| ----- | ----- | ----- |
| **Use Case** | Cross-region DR, global compliance, reducing read latency for distant users. | Log aggregation, synchronizing live and test environments, in-region compliance. |
| **Prerequisites** | Versioning must be **enabled on both source and target buckets**. | Versioning must be **enabled on both source and target buckets**. |
| **Existing Objects** | Not replicated automatically. Must use **S3 Batch Operations** for legacy data. | Not replicated automatically. Requires S3 Batch Operations. |
| **Delete Markers** | Not replicated by default (must explicitly configure delete marker replication). | Not replicated by default. |

| 💡 TIP: S3 Replication Time Control (RTC): Guarantees 99.99% of new objects replicated within 15 minutes. Select this for strict RPO (Recovery Point Objective) requirements. |

## **S3 Performance Optimization**

| Optimization Strategy | Implementation Details |
| ----- | ----- |
| **Prefix Scaling** | S3 automatically scales to support **3,500 PUT/COPY/POST/DELETE** and **5,500 GET/HEAD** requests per second **per prefix**. Use multiple prefixes (e.g., `/logs/2026/01/`, `/logs/2026/02/`) to achieve massive parallel request scale. |
| **Multipart Upload** | Strongly recommended for files `> 100 MB`; **mandatory for files `> 5 GB`**. Uploads parts in parallel to maximize throughput and retry individual failed chunks. |
| **S3 Transfer Acceleration** | Uses Amazon CloudFront’s globally distributed Edge Locations to route data over the AWS optimized backbone network via an accelerated URL. |
| **Byte-Range Fetches** | Requests specific byte ranges of a large object to download chunks in parallel or resume interrupted downloads. |
| **S3 Select / Glacier Select** | Runs SQL queries server-side to retrieve only specified subsets or attributes of data within an object, drastically reducing network bandwidth consumption and client processing effort. |

| ⚠️ EXAM TRAP: S3 is an **Object Store**, not a file system. You cannot natively mount S3 to EC2 as a block/file volume using standard OS commands. For shared network file systems, choose **Amazon EFS** (Linux) or **FSx** (Windows/High-Performance). |

## **S3 Decision Matrix for SAA-C03**

| Scenario / Requirement | Recommended S3 Solution |
| ----- | ----- |
| Store infrequently accessed reports that need instant millisecond access when auditors ask for them | **S3 Standard-IA** |
| Automatically optimize storage costs for unknown or unpredictable user access patterns without performance impact | **S3 Intelligent-Tiering** |
| Regulatory compliance requiring financial logs to be immutably preserved so that not even the root user can delete them | **S3 Object Lock in Compliance Mode** |
| Require audit logs showing every single time an encryption key is used to decrypt an S3 object | **S3 SSE-KMS** |
| Speed up file uploads coming from remote users across different continents | **S3 Transfer Acceleration** |
| Ensure S3 objects replicate across regions with a guaranteed 15-minute RPO SLA | **S3 Cross-Region Replication with S3 RTC** |
| High-performance parallel data uploads for files larger than 5 GB | **Multipart Upload** |
| Query specific rows out of large CSV/Parquet files directly in S3 without retrieving full objects | **S3 Select** |
